# Plan: Fix Redmi 10A APK Installation - Root Cause: Godot 4.4 Adaptive Icon Bug

## Problem Analysis

### Root Cause Identified
The error `Invalid ID 0x00000000` and `Parse error when parsing manifest` is caused by **Godot 4.4's export template bug**:

1. **Godot 4.4 export templates** generate adaptive icon resources (`icon_foreground`, `icon_background`, `icon_monochrome`) in the APK
2. The generated `AndroidManifest.xml` references these resources with **resource ID `0x00000000`** (null/invalid)
3. Android's package parser rejects manifests with invalid resource IDs
3. This is a **known Godot 4.4 bug** - the export template's `AndroidManifest.xml` has hardcoded adaptive icon references with zero resource IDs

### Evidence from Logcat
```
E/ackageinstalle: Invalid ID 0x00000000.
W/PackageInstaller: Parse error when parsing manifest. Discontinuing installation
```

### Why Previous Fixes Failed
- **Manifest rewriting**: Too complex, recompilation of resources fails on 9-patch PNGs
- **Resource removal**: aapt2 recompilation fails on system 9-patch drawables
- **Godot 4.4 template**: The bug is in the export template itself, not the export process

---

## Solution Strategy

### Option 1: Use Godot 4.3-stable (Recommended)
**Godot 4.3-stable** has **working multi-arch export templates** without the adaptive icon bug.
- Export templates include both `arm64-v8a` + `armeabi-v7a`
- No adaptive icon resource ID bug
- Build time: ~1-2 minutes
- **Risk**: API differences between 4.3 and 4.4 (minimal for 2D game)

### Option 2: Build Custom Export Templates from Source (Godot 4.4)
Build Godot 4.4 export templates from source with adaptive icons disabled.
- Requires modifying `platform/android/AndroidManifest.xml` in Godot source
- Build time: ~15-20 minutes
- **Risk**: Build complexity, potential compilation issues

### Option 3: Use Godot 4.2.2-stable (Most Stable)
Godot 4.2.2 has proven working export templates.
- **Risk**: More API differences

---

## Recommended Plan: Switch to Godot 4.3-stable

### Rationale
1. **Minimal API changes**: 4.3 → 4.4 is mostly bug fixes, 2D APIs stable since 4.0
2. **Working templates**: 4.3 export templates are multi-arch and bug-free
3. **Fast CI**: 1-2 minute builds
4. **Zero code changes**: Our game uses only core 2D APIs available in 4.0+

### Implementation Steps

1. **Update workflow**: Change `GODOT_VERSION` from `4.4-stable` to `4.3-stable`
2. **Update project.godot**: Change `godot_version="4.4"` to `godot_version="4.3"`
3. **Remove icon references**: Keep `icons={}` in export_presets (let Godot use default)
4. **Remove manifest fix script**: Delete `fix_manifest.sh` 
5. **Simplify workflow**: Remove merge step complexity if 4.3 templates are multi-arch
5. **Verify**: Build, download, test on Redmi 10A

### Fallback Plan
If 4.3 has issues → Use Godot 4.2.2-stable (even more stable)
